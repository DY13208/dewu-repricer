# 跟价引擎、调度与风控

## 引擎（engine/PricingEngine，纯函数）
1. 排除 SKU → SKIP；无竞争价/当前价 → SKIP。
2. 最低价来自同经营主体（含本店）→ HOLD，避免同主体店铺无休止互压。
3. 目标价 = 竞争价 −/=/+ 偏移（金额或百分比），按步长取整（低于/持平向下，高于向上）。
4. 底价 = max(最低售价, 满足利润底线的最低价)；利润 = 售价 − 平台费(费率，含上下限) − 履约费 − 成本；SKU 利润底线优先于策略。
5. 缺成本但要求利润 → BLOCK；底价 > 最高售价 → BLOCK。
6. 单次变化超过 max_change_ratio → BLOCK（熔断）并标记异常。
费率与费用须按商家合同与平台最新规则配置，系统不内置“官方费率”。

## 执行（task/RepricingExecutor）
紧急停止/店铺暂停检查 → 店铺熔断 → 店铺令牌桶限流（超限延迟重入队）→ 取当前价/竞争价并留快照 → 决策 → 全局或任务 DRY-RUN 时只记录 → 改价（任务项幂等键传给适配器）→ 回查（getUpdateResult，退化为 getCurrentPrice）→ 不一致标记 UNVERIFIED 异常。
可重试错误：指数退避+抖动，最多 max-attempts；不可重试直接 FAILED。店铺连续失败 10 次熔断 10 分钟。
重启恢复：启动时把 PENDING/RETRY 项重新入队；终态项再次执行直接返回（幂等）。

## 调度
Quartz cron（默认 10 分钟）检查每个店铺，按“店铺+scan_interval 时间窗口”生成幂等键创建任务，同店未完成的定时任务不会重复创建。频率以官方额度和压测为准：每店每轮调用约 2~4 次/SKU，需满足 `SKU数 × 调用次数 / 扫描间隔 ≤ QPS 额度`。
